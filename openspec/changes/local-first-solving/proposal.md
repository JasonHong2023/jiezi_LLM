## Why

使用者 2026-11-18：「請教 Claude 是最後手段，還是要讓模型學會自己解決問題」。現況的缺口：
- 本機說「不確定」時**直接**請教 Claude（程式註解：「本機重試沒有幫助」），沒有讓它再想一次；
- 網頁與 chat 都走串流，串流路徑查核沒過就直接轉交，**沒有**非串流路徑那一步「帶著錯誤訊息本機重答」；
- 思考模式預設關，從沒拿來當「想不出來時再深想一次」；
- 轉交過的題目只存進記憶，沒有變成下次本機自己會答的能力（工具、資料、訓練目標）。
Consult-on-unsure skips any local retry, streaming has no local retry, think mode is never used as a rung, and escalations never turn into local capability.

## What Changes

1. **本機先試到底的階梯**（串流與非串流一致）：
   1. 本機作答 → 查核；
   2. 沒過或說不確定 → **本機帶著錯誤訊息重答**（串流也做：畫面顯示「本機重想中」，答案換成新的）；
   3. 還不行 → **開思考模式再答一次**（限制思考 token，例如 1024；只在這一步開，平常照舊關）；
   4. 還不行 → 雲端免費模型只給**提示**，本機依提示再答（現有第 2 層，改成雲端優先）；
   5. 最後才請教 Claude。
   每一步都記在「過程」裡，看得到在哪一步解決。
2. **從轉交中學習**（遵守「Claude 的回答不當訓練資料」）：
   - 每晚把當天轉交的題目分類（現有 gaps 報告）：
     - 可以用程式算的 → 列為新工具候選（例：國定假日與補假）；
     - 資料缺口 → 找授權可用的資料來源；
     - 模型能力缺口 → 列入下一輪訓練目標，用授權資料訓練；
   - 本機在階梯第 2、3 步自己答對的題目，標為可訓練候選（本機自己的答案，不是 Claude 的）。
   - 每週回報：哪類題目還在轉、修了哪些。
3. **經驗記錄**（使用者 2026-11-18：「這些解決的過程他要記錄下來變成經驗」）：
   - 每次階梯走超過第 1 步，就在記憶 wiki 寫一筆「經驗」（`var/memory/wiki/experience/`，Obsidian 可看可改）：
     題目類型、第一次錯在哪（查核訊息）、哪一步解決、解決時的關鍵（例：「國定假日要先查補假規則，不要自己推算」
     「笑話不要照知識庫回答」）；由本機模型依過程摘要成一兩句「下次要注意」，不是存 Claude 的答案全文；
   - 下次遇到相似題目（和記憶相同的相似度比對），先把相關經驗當提示附給本機，讓它**第一次就答對**；
   - 經驗會累計：同一種錯誤再發生就加次數，經驗被用上且答對就記一次「有效」；三次以上無效的經驗自動停用；
   - 經驗可在網頁「狀態」或 wiki 檢視、修改、刪除；
   - 經驗只用來提示，不當訓練資料；從 Claude 解決的題目只記「本機錯在哪、該注意什麼」，不記 Claude 的答案內容。
4. **要上網的題目**（7 次）：本機目前沒有上網能力，只能轉。另案可評估加本機搜尋工具（例：自架 SearXNG），讓本機自己查網頁再回答；這次不做，先列為選項。

## Non-Goals

- 用 Claude 的回答訓練本機（規則不變）。
- 改變「答錯風險高時仍可請教 Claude」——Claude 仍是最後一層，只是不再是第一個選項。

## Capabilities

### Modified Capabilities

- `escalation`：新增 Local-First Escalation Ladder 需求。

## Impact

- 延遲：答不好的題目會多 1～2 次本機生成（每次約 5～30 秒），換來少請教 Claude；量測後回報。
- 量測：用 tune-knowledge-relevance 的真實題目與 E0 子集，比「階梯前後」的 Claude 次數、正確率、延遲（夜間）。
