## Context

2026-11-18 本機回答「台灣2027年的國定假日有哪些?」出錯，查核沒過後才轉 Claude；缺口報告指出這題可由程式依本機法規計算。 repo 已有《紀念日及節日實施條例》全文（`var/laws/laws.sqlite`，更新的 law id 會隨法規資料庫重建而變）、`lunar-python` 依賴，以及 tools 的落地／引用管線。

現況：OpenSpec change `add-holiday-tool` 已有 proposal、spec、tasks，但缺 `design.md`；`apply` state 為 `ready`，只要求 tasks。使用者 2026-11-19 明確授權「不換核心，計畫好就核准開始進行」。本設計把「計畫好」的實作邊界固定下來：只新增可計算的事實，不改模型、不新增依賴、不改核心權重。

## Goals / Non-Goals

**Goals:**

- 從本機法規資料庫讀《紀念日及節日實施條例》第 3、4、5、6、8 條，而不是把節日日期寫死在 Python 裡。
- 提供 `holidays(year)`：列出該年國定假日、星期、國曆／農曆節日換算，以及逢例假日的補假推算；補假標明「推算，以行政院人事行政總處公告為準」。
- 在 `tools.grounding` 針對國定假日／連假／補假問題附上【計算】與法規條號出處，讓本機模型照抄，不轉 Claude。
- 讀不到條文或解析失敗時，不附計算結果，照舊回答（降級不失誤）。
- 單位測試可在無 GPU、無網路、無雲端金鑰下跑過（R21.7）；2027 至少驗證除夕 2/5、春節連假、清明／兒童節。

**Non-Goals:**

- 不處理原住民族歲時祭儀、消防節／警察節、軍人節、海巡節等「依主管機關規定」的放假。
- 不保證行政院每年公告的調整放假／補行上班與推算完全一致；只注明推算與公告優先。
- 不改核心模型、不訓練、不引入新套件、不碰 R20 關卡或 add-sft-round2。

## Decisions

1. **新模組 `src/jiezi/holidays.py`，而不是塞進 `tools.py`。**  
   法規解析、節日換算、補假推算是獨立的 pure logic；放在獨立模組可單測，也可避免 `tools.py` 膨脹。對外只給 `holidays(year, laws=None)` 與 question cue / render helper。`tools.grounding` 負責何時呼叫與怎麼引用。替代：全部寫在 `tools.py`——較快但難測、難重複使用。

2. **條文是唯一資料來源，Python 只放「解析規則」。**  
   以 `Laws.article(law_id, num)` 逐條讀取；用正則拆解「名稱：日期」與「一、…。二、…。」列點。節日日期、放假清單、補假與兒童節／清明規則都來自條文文字；找不到Associated law 或必要條文就回 `None`。替代：在 Python dict 寫死日期——會跟修法漂移，違反提案。

3. **農曆與節氣交給既有 `lunar-python`。**  
   `Lunar.fromYmd(...).getSolar()` 換農曆節日；`LunarMonth.fromYm(y, 12).getDayCount()` 求除夕；`getJieQiTable()["清明"]` 求清明。替代：自己維護對照表——不可維護且會錯。

4. **補假採往例推算，不是宣稱官方公告。**  
   放假日逢星期六 → 前一個非周末、非假日的上班日；逢星期日 → 後一個非周末、非假日的上班日；日期去重並標 `estimated=True`。替代：不給補假——不能回答「連假／補假」；宣稱官方公告——會偽造未公告事實。

5. **grounding 附加而非取代。**  
   新計算包成與現有 appendix 相容的一段，明確標【計算】、列出條號與來源網址、附「以公告為準」；不覆蓋既有的法規／農曆引用。替代：直接把計算字串塞進模型回答——破壞既有 sources 結構與稽核。

6. **觸發條件收窄。**  
   僅問題同時有「國定假日／放假／連假／補假／holiday」語意與年份（四位數字或今年／明年／去年）時呼叫。替代：看到「台灣」就算——會干擾無關問題。

## Risks / Trade-offs

- [法規條文格式變動，解析失敗] → 解析失敗就回 `None`，由既有回答路徑處理；測試用真實 DB 與統一下載版本，登記資料日期。
- [農曆年末跨年：2027 春節落在 2026 農曆十二月] → 以「要求的西元年 y」的除夕 = 農曆 `y-1` 年十二月末日，往後五天；明確用 2027-02-05 驗證。
- [補假與實際公告不同] → 每筆補假都標推算，appendix 重複聲明「以行政院人事行政總處公告為準」；不寫成已公告。
- [children's day 與清明同日規則誤解] → 依條文第 6 條：同日時前一日放假，惟逢星期四改後一日； additional day 也列為假日並標來源。
- [重複假日：孔子誕辰 9/28 與教師節 9/28] → 同日合併顯示，但來源條號都保留。
- [每年法規 DB 重建後 law id 變動] → 用 `Laws.by_name["紀念日及節日實施條例"]` 查 id，不寫死 265。
- [SQLite 唯讀連線 thread safety] → 沿用 `Laws` 既有 `check_same_thread=False` 與 ro URI。

## 修正紀錄 / Amendment (2026-11-19)

- 原 Decisions #4 的通用往例（六補前、日補後）對春節不適用。查到人事總處 115.05.21 公告（https://www.dgpa.gov.tw/information?pid=12983&uid=82）：除夕及春節逢例假日得於前一個或次一個上班日補假；116 年初一、初二（2/6、2/7）補 2/9、2/10。已把 spring_dates 的補假方向改為往後，並讓補假日互相避開。
- 同公告亦載明 117 年 1/1 逢星期六，於 116/12/31 補假。已加入「隔年 1/1 逢星期六則補於當年最後上班日」規則；2027 清單因此包含 12/31。
- 2027 逐日結果已與公告附件／遠見、經理人、Open Data 轉載交叉比對：2/4–2/10、3/1、4/6、4/30、10/11、12/24、12/31 等補假一致；原本錯誤的 2/3 已移除。
