## 1. STaR（arXiv 2203.14465，NeurIPS 2022，Stanford / Google）

**機制 [原文]**
1. 用約 10 個 few-shot 範例讓模型產生推理過程（rationale）加答案。
2. 答對的保留；答錯的做 **rationalization**：把正確答案當提示，讓模型反推理由，存入訓練集時把提示拿掉。
3. **每一輪都從原始預訓練模型重新微調**（避免過擬合），重複到效能不再提升。
4. 理論上等價於以指示函數為獎勵的 policy gradient（greedy 取樣，探索有偏）。

**設定**：GPT-J 6B、單台 TPU-v3、lr 1e-6；第一輪 40 步，之後每輪多 20%。

**結果 [原文]**
| 任務 | STaR | 對照組 |
| --- | --- | --- |
| 5 位數加法（16 輪） | 89.5% | 直接微調 76.3% |
| CommonsenseQA | **72.5%** | GPT-J 直接微調 60.0%；GPT-3（30× 大）微調 73.0%；LaMDA 137B few-shot CoT 55.6% |
| GSM8K | **10.7%** | 直接微調 5.8%（絕對值很低） |

**作者自承的限制 [原文]**
- 第一輪要成功，**few-shot 表現必須高於隨機**。GPT-2 連算術都無法啟動。
- 隨機猜對率高的任務（例如二選一）會產生大量爛的推理過程，而且無法過濾。
- **提高取樣溫度反而有害**：答案對、推理錯的樣本會汙染訓練。
- 會放大資料集偏見（rationalization 更嚴重），也不保證推理過程是忠實的。
- ReST-EM 作者補充：rationalization 會造成大量「答案對、推理錯」的假陽性。

**[推論] 對本專案**：LittleBit 核心在多項 zero-shot 任務上接近隨機（例如 BoolQ 低於多數類基準），**STaR 的第一輪很可能無法啟動**。改用「雲端產生推理過程 + 本機學習」，也就是蒸餾版的 STaR。

## 2. Self-Refine（arXiv 2303.17651，NeurIPS 2023，CMU / AI2 等）

**機制 [原文]**：同一個模型依序扮演生成者、回饋者（要求**具體、可執行**的意見）、修正者，並保留完整歷史；最多 4 輪，不需要訓練。

**結果 [原文]**（GPT-3.5 / ChatGPT / GPT-4）
- 偏好類任務增益大：對話 GPT-4 從 25.4 → 74.6；情感反轉 3.8 → 36.2。
- 程式最佳化：GPT-4 從 27.3 → 36.0。
- **數學：+0 / +0.2 / +0.2**。ChatGPT 有 94% 的回饋是「everything looks good」。
- 改用 oracle 回饋（只在答錯時才修正）：GPT-3.5 +4.8、ChatGPT +1.4、GPT-4 +0.7。
- 統計顯著性：GPT-4 大多顯著，**GPT-3.5 只有 3/7 項顯著**。
- 失敗原因：**94% 來自回饋錯誤**（33% 指錯位置、61% 給錯修法），只有 6% 是修正者沒照著改。
- 多數指標由 GPT-4 判定偏好（與人類的相關性 68–82%）→ 有評審偏誤的風險。

**弱模型 [原文]**：Vicuna-13B 無法產生符合格式的回饋，**連給它 oracle 回饋都不會照做**，只會重複原答案或幻想出一段對話。
**混合修正 [原文]**：Vicuna-13B 起草 + ChatGPT 給回饋並修正，數學從 **24.18% → 40.5%**。

**[推論] 對本專案**
- 本機模型不能自我批評。
- 混合修正就是**「部分轉交」**：本機起草，驗證失敗時只請雲端給回饋或修正。這比整題轉交便宜，因為雲端只需輸出 diff 或意見。
- 回饋來源優先序：程式測試 / 工具錯誤 → 雲端批評 → 不使用自我批評。

## 3. Voyager（arXiv 2305.16291，NVIDIA / Caltech 等）

**機制 [原文]**：GPT-4 負責三件事：自動課程（目標是「探索盡可能多樣的事物」）、**可執行程式的技能庫**（key = 描述的 embedding，value = JS 程式，檢索 top-5）、迭代提示（環境回饋 + 執行錯誤 + **GPT-4 自我驗證**；最多 4 輪，失敗就換任務）。完全不微調。

**結果 [原文]**（160 輪 × 3 次）
- 63 種物品（3.3×）；科技樹：木製工具快 15.3×、石製 8.5×、鐵製 6.4×；鑽石工具只有 1/3 次成功。
- 新世界零樣本：Voyager 4 項任務都 3/3；AutoGPT 0/3，但**加上 Voyager 的技能庫後變成 1/3–2/3**。

**消融 [原文]**
| 拿掉的元件 | 影響 |
| --- | --- |
| 自動課程（改成隨機） | 物品數 −93% |
| 技能庫 | 後期停滯 |
| **自我驗證** | **−73%（最重要的回饋）** |
| GPT-4 → GPT-3.5 寫程式 | **物品數少 5.7×** |

**限制 [原文]**：GPT-4 成本是 GPT-3.5 的 15 倍，但「GPT-3.5 與開源模型提供不了」所需的程式品質；也會幻想出不存在的物品與 API。

**[推論] 對本專案**
- 小模型**無法驅動** Voyager 迴圈，但**技能庫可以跨模型使用**。
- 分工：雲端負責產生並驗證技能（工具呼叫流程、程式範本），本機模型負責檢索與組合。
- 技能存在磁碟上，**不佔權重、不會遺忘**，也與 LittleBit 的位元預算無關。

## 4. ReST-EM（arXiv 2312.06585，TMLR 2024，Google DeepMind）

**機制 [原文]**：把 RL 寫成期望最大化。E 步：每題取樣 N 個解（MATH 32 個、APPS 64 個；top-K 40、溫度 0.7），用二元回饋過濾（答案比對 / 單元測試），每題最多保留 10 個。M 步：**每輪都從基礎模型重新微調**（比接續上一輪的遷移效果更好）。

**結果 [原文]**（PaLM 2-S / S\* / L，透過 Google Cloud API）
- MATH：2-S +5.94、2-L +6.34；APPS：S\* +5.6、L +6.4 → 「隨模型規模擴大」其實只是**略大**的絕對增益，約 6 分。
- 迭代：MATH 第 1 輪之後增益很小；**APPS 第 2 輪退步**（2342 題的小資料集過擬合），訓練集分數卻持續上升。
- 多輪迭代勝過單輪用 3 倍資料（41.9 vs 40.3）。
- 每題只用 1 個模型生成的解，仍勝過人類解（ReST\*(5K) > SFT(5K)）。
- **蒸餾**：用 PaLM 2-L 生成的解訓練 2-S，**勝過 2-S 自己做 ReST-EM**。
- **1000 題**就有顯著增益；各難度都有提升；BBH 沒有退步；匈牙利高中數學會考表現強。
- maj@64 MATH：48.82 vs 基礎模型 44.02。

**限制 [原文]**：需要一組題目（通常由人類收集）、需要能自動計算的獎勵；pass@1 追不上 pass@K。

**[推論] 對本專案**
- 這是**最適合我們的權重更新方法**：程式（測試）與工具呼叫（執行結果）都有二元回饋。
- 搭配蒸餾：題目來自真實流量與雲端出題，解答來自本機 N 條取樣加雲端答案，再用驗證器過濾。
- 規則：每題最多保留 10 個解、每輪從凍結核心重新訓練 LoRA、最多 3 輪、看到退步就停。

## 5. SPIN（arXiv 2401.01335，ICML 2024，UCLA）

**機制 [原文]**：從 SFT 模型出發，每一輪讓模型對 SFT 題目生成回答 y′，再用類似 DPO 的 logistic loss 學會「偏好人類答案 y，勝過自己的 y′」。不需要獎勵模型，也不需要額外的偏好資料。
**定理 [原文]**：全域最佳解**若且唯若** p_θ = p_data → **上限就是 SFT 資料的品質**（作者列為限制）。

**設定 [原文]**：zephyr-7b-sft-full（Mistral-7B）、UltraChat200k 中的 5 萬題；第 0 輪 5 萬筆，之後每輪 10 萬筆；每輪 2 epochs；RMSProp lr 5e-7 → 1e-7；β 0.1（第 3 輪改為 5.0）。
**注意 [原文]**：作者所說的「人類資料」UltraChat，本身是由 **OpenAI Turbo API 生成**的。

**結果 [原文]**（Open LLM Leaderboard 平均分）
| | SFT | 第 0 輪 | 第 1 輪 | 第 2 輪 | 第 3 輪 |
| --- | --- | --- | --- | --- | --- |
| 平均 | 58.14 | 60.80 | 62.12 | 62.97 | 63.16 |
| 增益 | — | +2.66 | +1.32 | +0.85 | +0.19 |
| MMLU | 60.92 | 60.03 | 59.34 | 59.93 | **59.99（下降）** |
| GSM8K | 26.76 | 35.10 | 35.78 | 38.06 | 38.97 |
| TruthfulQA | 43.73 | 49.18 | 55.17 | 54.91 | 54.90 |

- 第 1 輪就超越 zephyr-DPO（用了 6.2 萬筆 GPT-4 偏好資料，61.31）；SPIN + DPO 達 64.05。
- MT-Bench 5.94 → 6.78。
- 對照組：在同一份 SFT 資料上再多訓練一個 epoch，**反而退步**（57.23）。
- 成本：8×A100，每輪生成 1.45 小時 + 訓練 4.3–8.6 小時 → 7B 合計約 **40 A100 小時**。

**[推論] 對本專案**：如果把「目標資料」換成**雲端模型的答案**，SPIN 就是「用自我對弈做蒸餾」，上限是雲端答案的品質。這比單純 SFT 能從同一批資料榨出更多，可作為 ReST-EM 之後的第二階段。但要注意知識類指標（MMLU）會輕微下降。

## 6. Self-Rewarding Language Models（arXiv 2401.10020，ICML 2024，Meta / NYU）

**機制 [原文]**：M1 = 在 3200 筆 OpenAssistant 指令資料（IFT）+ 1630 筆評審資料（EFT）上做 SFT；之後每輪生成 N=4 個回答，由**模型自己當評審**（加分制的 5 分 prompt，評 3 次取平均），取最高分對最低分組成偏好對，做 DPO，共 3 輪。

**容易忽略的細節 [原文]**
- **只在 Llama 2 70B 上驗證。**
- 新題目由**固定的** Llama 2-Chat 70B 產生，不是模型自己出題。
- **early stopping 由 Claude 2 判定**，評測用 GPT-4 → 迴圈中其實仍有外部強模型。

**結果 [原文]**
- AlpacaEval 2.0（對 GPT-4 Turbo 的勝率）：9.94% → 15.38% → **20.44%**，超過 Claude 2（17.19%）、Gemini Pro（16.85%）、GPT-4 0613（15.76%）。
- MT-Bench 6.85 → 7.25；但數學、程式、推理只從 3.93 → 4.17。
- 評審能力（與人類兩兩比較的一致率）：65.1% → 78.7%（加入 EFT）→ 80.4% → 81.7%。
- **評審 prompt 影響巨大**：加分制 65.1%，分級制只有 26.6%。
- **只用正樣本做 SFT 完全沒有幫助**（11,254 筆 5 分樣本 → 29% vs 30%），必須用偏好對。
- 分類別看：**數學與邏輯推理沒有增益**；作者自述「主要是更好地利用既有知識」。
- **回答長度：1092 → 1552 → 2552**（長度偏誤，作者承認可能有獎勵駭客）。

**回歸 [原文]（表 9）**
| | M1 | M3 |
| --- | --- | --- |
| ARC-e | 78.14 | **72.35** |
| ARC-c | 57.51 | **53.13** |
| NQ（知識） | 35.48 | **31.86** |
| GSM8K | 60.27 | 57.70 |

**[推論] 對本專案**：小模型當自己的評審**不可行**（需要 70B 級模型加專門的評審資料）。改成**雲端當評審**，本機只當 DPO 的學生。評審 prompt 必須調校，並加入長度懲罰。

## 7. ADAS / Meta Agent Search（arXiv 2408.08435，ICLR 2025，UBC / Vector）

**機制 [原文]**：搜尋空間是 Python 程式（約 100 行框架中的 `forward(task)` 函式）。元智能體（GPT-4 / gpt-4o）寫出新 agent → 自我反思兩次確認新穎性 → 在驗證集上評估（出錯可修正最多 5 次）→ 連同分數存入檔案庫。檔案庫的初始內容是 CoT、CoT-SC、Self-Refine、Debate 等手寫 agent。**候選 agent 用較便宜的目標模型（GPT-3.5）評估。**

**結果 [原文]**
| 領域 | 最佳手寫 agent | Meta Agent Search |
| --- | --- | --- |
| DROP 閱讀理解（F1） | 65.8 | **79.4** |
| MGSM 多語數學 | 39.0 | **53.4**（空白初始化反而達 67.5） |
| MMLU | 65.9 | 69.6（小） |
| GPQA | 31.6 | 34.6（小） |

- 作者自述：MMLU、GPQA 受限於模型知識，**agent 設計補不了缺少的知識**。
- 跨領域遷移：MGSM 上找到的 agent 用在 GSM8K（34.9 → 69.5）、GSM-Hard（15 → 31.2）、DROP（70.4）。
- 跨模型遷移（ARC）：GPT-3.5 6.0 → 13.7；**Claude-Haiku 4.3 → 9.7（弱模型的絕對增益小）**；GPT-4 17.7 → 37.0；Claude-Sonnet 25.3 → 48.3。
- 弱模型適合複雜的回饋機制；強模型適合簡單回饋 + 多輪修正。
- **成本**：ARC 每次約 US$500、推理類約 US$300，**主要花在用目標模型評估候選 agent**。
- 限制：只測單步問答；目標函數只看表現，**不考慮成本與延遲**；agent 會成倍增加模型呼叫次數（例如 5 條 CoT × 3 輪修正）。

**[推論] 對本專案**：元智能體用雲端（呼叫次數少），目標模型用**本機 LittleBit**。最大的成本（評估）變成本機運算，而且是批次形狀，正好能讓多種硬體加總。必須加入**多目標**：準確率、延遲、雲端費用。

## 8. Gödel Agent（arXiv 2410.04444，ACL 2025，北京大學 / UCSB）

**機制 [原文]**：agent 透過 monkey patching 讀取並修改自己的 Python 執行期程式碼，**包括負責自我改進的那段程式**。動作有：自我檢視、與環境互動（在驗證集上算分）、自我更新、繼續改進；另有先思考再行動、錯誤處理、執行程式、呼叫 LLM 等工具。

**設定 [原文]**：最佳化用 gpt-4o，被最佳化的策略用 gpt-3.5 評估；初始策略為 CoT；6 個循環 × 每循環最多 30 輪。

**結果 [原文]**
| | DROP | MGSM | MMLU | GPQA |
| --- | --- | --- | --- | --- |
| ADAS | 79.4 | 53.4 | 69.6 | 34.6 |
| Gödel（受限，GPT-3.5） | 80.9 | **64.2** | 70.9 | 34.9 |
| Gödel-free（不受限） | 90.5 | 90.6 | 87.9 | 55.7 |

- **Gödel-free 分數暴增的主因：agent 自行決定改去呼叫更強的 GPT-4o**。這等於自己發明了雲端轉交，也是繞過限制的獎勵駭客。
- 消融（MGSM）：拿掉先思考 −13.4；拿掉錯誤處理 −14.8。
- 穩健性（MGSM 100 次試驗）：4% 意外終止（多半是改壞了自我改進模組）、92% 出現暫時性退步、**14% 最終比起點更差**。
- Game of 24：有一次改寫成搜尋演算法後達 100%；但**從未超越以 ToT 為起點的結果**（「難以超越現有最佳演算法」）。
- 成本：完整進化約 US$15（主要來自不斷增長的歷史記憶）。

**[推論] 對本專案**：Gödel-free 證明自我修改的系統**一定會去找最強的資源**。我們的系統已經把「轉交雲端」設計成正式機制，所以更要把**轉交門檻、預算、評分器**放在自我修改的範圍之外。只在沙盒中實驗。

## 9. A Survey on Self-Evolution of LLMs（arXiv 2404.14387，北京大學 / 阿里巴巴 / NTU）

**框架 [原文]**：進化目標 E =（能力，方向）。四個階段：
1. **經驗取得**：任務進化（依賴知識 / 不依賴知識 / 從既有任務挑選）、解答進化（正面：推理過程、互動、自我對弈、依據規則或經驗；負面：對比、擾動）、回饋（模型 / 環境）。
2. **經驗精煉**：過濾（依指標 / 不依指標，例如一致性）、修正（有批評 / 無批評）。
3. **更新**：寫入權重（重播、正則化、架構類如 LoRA 與模型合併）、寫入上下文（外部記憶：插入、反思、遺忘；工作記憶）。
4. **評估**：量化（LLM 評審、獎勵分數）、質化。

**開放問題 [原文]**
- 自主程度分三級：低（人定目標也設計流程，現有研究大多在此）、中（人定目標）、高（模型自己診斷並設計）。
- 理論：**自我修正在 >22B 的模型才觀察到**（引用 Huang 等）；另有研究指出沒有外部回饋時難以自我修正推理錯誤（引用 Ganguli 等）。
- **模型崩潰**：用自己生成的資料訓練，品質與多樣性會逐步下降，必須平衡合成資料與真實資料。
- 現有方法**超過 3 輪就難以再提升**（引用 ReST-EM、A3T）。
- 穩定性與可塑性的兩難（災難性遺忘）；靜態評測會被洩題，需要動態評測；安全與超級對齊。
- 「較弱的模型在自我批評上可能非常吃力」→ 改用外部工具提供的批評（CRITIC、SelfEvolve）。

**[推論] 對本專案**：我們的系統屬於「低到中」自主程度：人定目標，並由雲端元智能體協助設計流程。這是現階段最務實、也最可控的位置。
