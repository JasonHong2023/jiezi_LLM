## 0. 目標與已確立的決策

**目標**：以最小的硬體成本，做出能力最大的多功能通用模型；模型採用 **LittleBit 形式**，並能組合使用所有可用的運算硬體（CPU / GPU / NPU）。

| 項目 | 決策 | 日期 |
| --- | --- | --- |
| 模型形式 | LittleBit（低秩分解 + 二值因子 + 列/行/潛在縮放） | 11-14 |
| 評測任務 | 中文問答、寫程式、文件摘要、工具呼叫（其他要素待補） | 11-14 |
| 雲端轉交 | **必要元件**：本機信心不足時轉交雲端 | 11-14 |
| 推論引擎 | ggml / llama.cpp 優先，ORT 之後再評估 | 11-12 |
| 能力提升手段 | 納入自我進化（9 篇文獻，見 §5） | 11-14 |

**成功指標**（R0 建好後量化）

| 指標 | 定義 |
| --- | --- |
| 達成率 | 本機系統分數 ÷ 雲端模型分數（每類任務分開算） |
| 本機處理率 | 不需要轉交雲端的請求比例 |
| 單位成本 | 每 1000 個請求的雲端費用 + 本機電費 |
| 硬體成本 | 達到目標所需的最低硬體規格 |

## 1. 四條硬限制（所有設計都必須遵守）

1. **單一請求的解碼無法加總多個裝置。** 解碼受記憶體頻寬限制、逐層依序執行；把模型切在多個裝置上，時間是相加而非取最大值。本機實測：CPU 從 6 到 20 執行緒，解碼都停在約 24 t/s **[實測 11-14]**。
   → 硬體要能「加總」，工作必須是**批次形狀**：平行取樣、多請求、資料生成、任務管線。
2. **知識容量受儲存位元數限制。** 模型能記住的事實，上限是它實際儲存的位元數。Qwen3-8B @ 0.55 BPW 的區塊約 4.4 Gbit，Qwen3-1.7B Q4_K_M 約 7.6 Gbit **[自算]**。
   → LittleBit 要贏，前提是「低秩 + 二值」每個位元能存的知識比 4-bit 量化更多。這不是必然，**必須用 E1 驗證**。
3. **驅動自我進化需要大模型。** STaR：GPT-2 無法啟動；Self-Refine：Vicuna-13B 失敗；Self-Rewarding 只在 70B 上驗證；Voyager 把 GPT-4 換成 GPT-3.5 後少了 5.7×；Survey：自我修正約在 >22B 才出現 **[原文，詳見 `../analysis/self-evolution-papers.md`]**。
   → LittleBit 核心**只當學生與執行者**；回饋訊號來自**外部**：程式執行、測試、工具結果、雲端模型。
4. **自我進化無法創造知識。** ADAS/Gödel 在 MMLU、GPQA 幾乎沒有增益；Self-Rewarding 的 NQ 從 35.5 降到 31.9；SPIN 的 MMLU 下降 **[原文]**。
   → LittleBit 流失的知識只能靠 **RAG** 補；E1 必須把知識題和推理/工具題**分開評分**。

## 2. LittleBit 核心模型

### 2.1 方法摘要 **[論文]**
`W ≈ diag(h)·U_sign·diag(ℓ)·V_signᵀ·diag(g)`，主路徑加殘差路徑；用 Dual-SVID 初始化，再以 QAT + 知識蒸餾訓練（約 1B tokens、5 epochs）。甜蜜點是 0.3–0.55 BPW。

### 2.2 論文的弱點（詳見 `2026-11-14.md` 的論文分析）
- 主要對手是免訓練的 PTQ，評測資料和訓練資料同源。
- 扣掉隨機基準後，zero-shot 能力只剩 21–38% **[自算]**。
- embedding / `lm_head` 保持 FP16，佔 7B 模型大小的約 83% **[自算]**。
- 沒有 70B 的品質數據；11.6× 加速是挑選過的單層 kernel 數字，端到端只有 2.46×；KV cache 壓縮沒有處理 RoPE。

### 2.3 我們的改良版本
| 改良 | 理由 |
| --- | --- |
| 區塊用 LittleBit，**詞表層用 ggml K-quant**（embedding Q4_K、`lm_head` Q6_K/Q4_K） | Qwen3-8B 的詞表層若保持 FP16 約 2.5 GB，比區塊（約 0.47 GB）還大 **[自算]** |
| 以 ggml `Q1_0` 存放 ±1、F16 存放縮放向量 | 盡量不寫新 kernel（**待驗證 `Q1_0` 的 `mul_mat` 支援度**） <br>**更正（2026-11-15，R19.4）**：鎖定版本 `93cf736a` 的原始碼中，`Q1_0`（每 128 個一組）出現在 CUDA 的 `convert.cu`、`mmvq.cu`、`getrows.cu` **[本機查證：原始碼]**，主線也已能跑 PrismML 的 1-bit Bonsai。尚未以 `test-backend-ops` 實測。 |
| 自我進化的權重更新走 **LoRA 疊在凍結的 LittleBit 核心上**（§5.5） | 打包後的二值權重無法直接微調 |

### 2.4 官方程式碼事實 **[查證]**
- `SamsungLabs/LittleBit`，授權 CC BY-NC 4.0（**禁止商用**）；支援 Qwen3（僅 dense，沒有 MoE）。
- 前向計算：`littlebit.py:118`；打包格式：`binary_packer` 每 32 個元素存成一個 `int32`。
- **沒有釋出 CUDA kernel，也沒有官方權重。**

### 2.5 E1：決定成敗的關卡
| 組別 | 模型 | 大小 |
| --- | --- | --- |
| A | Qwen3-8B @ 0.55 BPW + 詞表 K-quant | ~1.2 GB |
| B | Qwen3-1.7B Q4_K_M | 1.1 GB |
| A' | Qwen3-14B @ 0.3 BPW + 詞表 K-quant | 待算 |
| B' | Qwen3-4B Q4_K_M | ~2.5 GB |

- **A 勝 B** → LittleBit 路線繼續。
- **A 輸 B** → 核心改用「小 dense/MoE 模型 + 4-bit」，§3–§5 的系統層**全部照常保留**（它們與核心形式無關）。
- 訓練成本約 33 H100 小時、US$70–100 / 次 **[推論，±2×]**。
- **評分要拆成兩組**（依 §1 第 4 點）：知識題（中文問答）與推理/工具題（程式、工具呼叫、摘要）。可能的結果是 A 在知識題輸、在工具題加 LoRA 後贏；這時的決策是「LittleBit + RAG」，而不是直接放棄。

## 3. 異質硬體分工

| 硬體 | 擅長的工作 | 在本系統中的角色 |
| --- | --- | --- |
| GPU（RTX 4050，可用 4896 MiB） | 頻寬高（192 GB/s）、算力強 | 核心模型生成 + 平行取樣 |
| CPU（14 個虛擬核，RAM 可用 12010 MiB） | 容量大、分支邏輯強 | 驗證器（執行程式/測試）、工具、檢索、溢出的批次 |
| NPU（本機沒有） | 低功耗、固定 shape | embedding / rerank（hetero-runtime S4） |
| 雲端 | 最強品質 | 轉交防線 + **教師 / 評審**（§5） |

**硬體真正「加總」的地方**：平行取樣（GPU 跑 N 條，CPU 同時驗證上一批）、離線資料生成（夜間批次），以及任務管線。

## 4. 推論期系統架構

```
請求 ─▶ gateway
          ├─▶ 技能庫檢索（雲端建立並驗證過的工具流程、程式範本）  ← Voyager
          ├─▶ RAG（知識外置；自我進化補不了知識）
          ├─▶ LittleBit 核心 × N 條平行取樣                       ← 硬體加總
          ├─▶ 驗證器（程式測試 / 工具 schema 與執行 / 格式檢查）
          │      ├─ 通過且一致 ─▶ 回覆（第 0 層：純本機）
          │      ├─ 失敗但可修 ─▶ 依驗證器錯誤訊息在本機重試（第 1 層）
          │      ├─ 仍失敗     ─▶ 只請雲端給「回饋 / 修正」（第 2 層：部分轉交）← Self-Refine 混合修正
          │      └─ 低信心     ─▶ 雲端完整回答（第 3 層：完整轉交）
          └─▶ 軌跡記錄器（問題、N 條本機答案、驗證結果、所在層級、雲端內容、費用）
```

**分層轉交**：Self-Refine 的混合修正實驗中，Vicuna-13B 起草 + ChatGPT 修正，數學從 24.18% 提升到 40.5% **[原文]**。第 2 層只需雲端輸出意見或 diff，費用低於整題轉交。各層的比例就是成本儀表板的核心。

## 5. 自我進化（9 篇全文分析後的採用方式）

> 逐篇全文分析見 [`../analysis/self-evolution-papers.md`](analysis/self-evolution-papers.md)。

### 5.1 核心原則（由 8 項跨論文發現推導）

| # | 原則 | 依據 **[原文]** |
| --- | --- | --- |
| P1 | **雲端當老師、評審、元智能體；本機只當學生與執行者** | 驅動迴圈需要 ≥13B，多數只在 GPT-4 / 70B 上驗證 |
| P2 | **外部驗證優先於一切自我判斷** | Voyager 拿掉自我驗證 −73%；Self-Refine 數學自評 +0、oracle +4.8 |
| P3 | **知識靠 RAG，不靠進化** | ADAS/Gödel 在 MMLU/GPQA 幾乎沒有增益；Self-Rewarding NQ 下降 |
| P4 | **向強者學（主幹）：老師要更強，但必須在學生「學得會」的距離內** → 採「老師階梯」，見 §5.7 | ReST-EM：L→S 蒸餾勝過 S 自我訓練；BitDistill：用 1.7B/4B 教 0.6B 三值模型，勝過同尺寸 FP16；**反例** ScaleQ/AYOT：壓縮時用 DeepSeek-R1-671B 的推理過程（31.8）遠不如模型自己 FP 版本生成的（58.4） |
| P5 | **每輪從凍結核心重新訓練，最多 3 輪** | STaR / ReST-EM 都從基礎模型重訓；SPIN 增益遞減；Survey：>3 輪停滯 |
| P6 | **驗證過的資料用 SFT；評審打分的資料用偏好對（DPO）** | ReST-EM 正樣本 SFT 有效（有正確性驗證）；Self-Rewarding 只用 5 分樣本 SFT 無效 |
| P7 | **回歸關卡涵蓋全部任務 + 長度 + 延遲** | Self-Rewarding ARC-c −4.4、長度 2.3×；SPIN MMLU 下降 |
| P8 | **自我修改不得觸碰評分器、預算、轉交門檻** | Gödel-free 自行改呼叫 GPT-4o；Self-Rewarding 靠拉長回答拿分 |

### 5.2 九篇論文的採用決策

| 論文 | 決策 | 採用的部分 | 不採用的部分與原因 |
| --- | --- | --- | --- |
| STaR | 🔄 改造 | 「只保留答對的推理過程」、每輪從基礎模型重訓 | 本機自行產生推理過程：核心接近隨機時無法啟動 → **改由雲端產生推理過程**；rationalization 會產生假陽性 |
| Self-Refine | 🔄 改造 | 迭代修正、保留歷史、依分數選最佳 | 自我批評：弱模型失敗 → **驗證器錯誤訊息（第 1 層）+ 雲端批評（第 2 層）** |
| Voyager | ✅ 採用 | **技能庫**（embedding 索引的可執行程式）、自動課程、驗證後才入庫 | 由本機驅動：GPT-3.5 已少 5.7× → 技能由雲端建立 |
| ReST-EM | ✅ **主力** | 取樣 N 條 → 二元驗證過濾 → 每題最多 10 筆 → 從核心重訓 LoRA；搭配雲端解答做蒸餾 | — |
| SPIN | ⚠️ 第二階段 | 以**雲端答案**為目標分布做自我對弈，從同一批資料榨出更多 | 上限等於目標資料品質；注意知識指標下降 |
| Self-Rewarding | 🔄 改造 | 迭代 DPO、加分制評審 prompt、評審評 3 次取平均 | 自己當評審：需要 70B → **雲端當評審**；加入長度懲罰 |
| ADAS | ✅ 採用 | 雲端元智能體搜尋工作流程程式碼，**以本機模型評估**（成本轉為本機運算） | 單一目標 → 改為多目標：準確率、延遲、雲端費用 |
| Gödel Agent | ⏸ 延後 | 錯誤處理與先思考再行動的設計 | 自我修改：14% 結果比起點差、會繞過限制 → 只在沙盒中，且不得觸碰護欄 |
| Survey | ✅ 框架 | 四階段飛輪、三級自主程度（我們定位在低到中） | — |

### 5.3 進化飛輪

| 階段 | 做法 | 執行位置 |
| --- | --- | --- |
| 經驗取得 | 真實流量軌跡 + 第 2/3 層的雲端內容 + 雲端出題的夜間課程 | 本機批次取樣（硬體加總） |
| 經驗精煉 | 驗證器過濾（P2）→ 雲端評審打分（加分制 + 長度懲罰）→ 去重、每題最多 10 筆 | CPU 驗證 + 雲端 |
| 自我更新 | 依成本由低到高：① 技能庫 ② 工作流程（ADAS）③ LoRA：SFT（驗證過的資料）/ DPO（評審打分的資料）④ 雲端重新 QAT 合併 | 本機 → 雲端 |
| 評估 | **R0 回歸關卡**：四類任務都不得退步超過 1 分，回答長度增幅 < 20%，延遲不變差；否則回滾 | 本機 |

### 5.4 更新層級的成本與風險

| 層級 | 成本 | 遺忘風險 | 備註 |
| --- | --- | --- | --- |
| ① 技能庫 | ≈ 0 | 無 | 可跨模型使用（Voyager → AutoGPT 已驗證） |
| ② 工作流程（ADAS） | 雲端元智能體的 API 費用；評估在本機 | 無 | 論文中 US$300–500 的大頭（評估）在本機變成近乎免費 **[推論]** |
| ③ LoRA | 本機 GPU 數小時 | 中 | rank 8 對 4096² 的層約 +0.06 BPW **[自算]** |
| ④ 重新 QAT | 約 US$100 / 次 | 中高 | 必須保留潛在 FP checkpoint |

### 5.5 LittleBit 與 LoRA 的結合
打包後的 ±1 權重不能直接微調，因此採用類似 QLoRA 的做法：凍結 LittleBit 核心，只訓練 FP16 LoRA。每一輪都從**凍結核心 + 全新 LoRA** 開始訓練（P5），而不是在上一輪的 LoRA 上繼續。LoRA 累積到一定量後，合併回保存的潛在 FP 權重，在雲端重新 QAT 並二值化（層級 ④）。

### 5.6 護欄
1. **雲端服務條款**：部分商業 API 禁止用其輸出訓練競爭模型。使用前逐一確認，必要時改用允許蒸餾的模型或開源大模型當老師。
2. **模型崩潰**：自我生成資料設比例上限，永遠混入原始資料與雲端資料（Survey）。
3. **災難性遺忘**：每次更新都要通過 R0 回歸關卡（P7）。
4. **獎勵駭客**：評審 prompt 加長度懲罰；所有自我修改的元件都不得觸碰評分器、預算、轉交門檻（P8）。
5. **隱私**：軌跡只存本機；送往雲端的內容可選擇去識別化。
6. **沙盒**：ADAS / Gödel 產生的程式碼一律在容器中執行（兩篇論文的作者也都這麼做）。

### 5.7 老師階梯：「向強者學」的具體做法

**核心觀念**：「強者」不只是雲端大模型，**壓縮前的自己（FP 原版）也是強者**。三篇論文合起來看：老師太弱學不到東西；老師太強（架構與規模差太多），學生也模仿不來（AYOT 中 R1-671B 的推理過程反而有害）。**[推論]**

| 階梯 | 老師 → 學生 | 用在哪個階段 | 依據 **[原文]** |
| --- | --- | --- | --- |
| 1 | **FP 原版的自己** → 壓縮後的核心（LittleBit / 三值） | 壓縮與校準（L0、E1） | AYOT：自己生成的資料 58.4 vs R1 31.8；LittleBit / BitDistill 都以 FP 原模型為 KD 老師 |
| 2 | **同家族大一號的模型**（例如 Qwen3-14B/32B）→ 核心 | 壓縮後的能力提升（V3 的 LoRA / KD） | BitDistill：大老師帶來更大增益；ReST-EM：L→S 蒸餾 |
| 3 | **寬鬆授權的開源大模型** → 技能庫、工作流程、驗證器、訓練資料 | V1 / V2 / V3 | ToolRM 只用寬鬆授權的開源模型生成訓練資料；服務條款安全 |
| 4 | **商業雲端模型** → 推論期的修正與轉交、評審、元智能體 | R3（第 2/3 層轉交）、V2（ADAS） | Self-Refine 混合修正（24.18 → 40.5）；ADAS 以 GPT-4 當元智能體。**用於訓練前必須確認服務條款** |

**原則**
1. 每往下一階，老師的答案都要先經過**驗證器過濾**（P2）再當教材。
2. 差距太大時，用中間一階「轉譯」：例如先由大模型產生題目與參考答案，再由 FP 原版的自己用自己的風格重寫推理過程，最後才給壓縮後的核心學（結合 AYOT 與 ReST-EM）。**[推論，待 E1/V3 驗證]**
3. 這條階梯本身就是自我進化的飛輪：核心變強 → 第 0 層處理率上升 → 轉交減少 → 每次轉交都更集中在「核心真正不會」的題目上 → 下一輪教材更精準。

## 6. 整合路線圖

| 階段 | 內容 | 驗收 | 依賴 |
| --- | --- | --- | --- |
| **R0** | 四類任務題庫（各 30 題起步，**知識題與推理/工具題分開**）+ 評分器 + 雲端基準分數 | 能自動算出達成率 | — |

## 7. 風險總表

| 風險 | 機率 | 影響 | 對策 |
| --- | --- | --- | --- |
| E1 失敗（LittleBit 不如同大小的小模型） | 中高 | 核心形式改變 | 系統層與核心形式無關，照常推進 |
| `Q1_0` 不支援所需的 `mul_mat` | 中 | L1 工作量大增 | 先查原始碼；不行就以 `Q8_0` 或 F16 暫代 ±1 驗證正確性 |
| ↳ **更正（2026-11-15）** | 低（原始碼已有 CPU 與 CUDA 路徑，待 `test-backend-ops` 實測） | — | E0 的 1-bit Bonsai 實跑可作為第一個證據 |
| 小模型的自我進化收益很小 | **高**（9 篇文獻一致） | V3 效益低 | P1：雲端當老師與評審；先做 V1/V2（不改權重）再做 V3 |
| 知識流失無法靠進化補回 | 高 | 中文問答達成率低 | P3：RAG（R4）優先於 V3；E1 分組評分 |
| 進化後在其他任務退步 / 回答變長 | 中 | 整體品質下降 | P7 回歸關卡 + 長度懲罰 |
| 自我修改元件繞過限制 | 中（Gödel 已示範） | 成本失控 | P8：護欄不在可修改範圍內 |
| 雲端服務條款禁止蒸餾 | 中 | V3 資料來源受限 | 開源大模型當老師；先查清條款 |
| 授權 CC BY-NC | 確定 | 不可商用 | 若要商用，需自行從論文重新實作 |
| 6 GB VRAM 跑不動 L0 | 中 | 本機無法驗證流程 | 縮短序列、gradient checkpointing，或改租小型雲端 GPU |
